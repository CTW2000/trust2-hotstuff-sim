# 信任 2.0 现行规范（对应论文 v11 及之后，git 标签 `paper-v11`，2026-11-12）

这份文件只记录现行规则和默认参数，供独立实现逐位核对。规则的来龙去脉、历史配置和实验记录见 `DESIGN.md`，那里保留了已被替换的版本，不应当作规范引用。所有时长按视图计；默认纪元长度为 25 个视图，以 100 个视图为参考纪元的参数按视图数折算（`epoch::scaled`）。

## 1. 名册与 CapNorm（`consensus/src/ttru.rs`）

- **实体：**同一受益所有人的节点合并为一个实体，原始权重 $w_k$ 为成员权重之和；类别为持牌或未认证。
- **只计正权重：**原始权重为 0 的实体份额为 0，不计票、不参与领导者抽取，也不计入可行性判断。
- **未认证类份额：**$U=\min(\text{未认证原始份额},\,u_{\max},\,n_U\cdot\mathrm{cap})$，$n_U$ 为正权重未认证实体数；持牌类分得 $1-U$。
- **拒绝名册（不放宽上限）：**以下情形 `base_weights` 返回 `Infeasible`：没有任何正权重（`Empty`）；没有正权重的持牌实体（`NoLicensed`）；$n_L\cdot\mathrm{cap}<1-U$（`Cap`）。
  - 创世名册被拒绝时，节点拒绝启动（`check_roster`，`node.rs`）。
  - 会使名册被拒绝的准入、退出、类别变更或合并不生效（方案规定；原型为固定名册）。
  - 分叉逐出后余下名册被拒绝时，不重算，只把被逐出者的基础份额记为 0（`Punishment::evict`）。
- **注水封顶：**每类内部按原始权重成比例分配，超过 cap 的实体固定为 cap，其余份额按原比例分给未封顶的实体，直到没有实体超过 cap。
- **定点与取整：**份额以 $10^{18}$ 为 1，每步向下取整。

## 2. 纪元表（`ttru::table`、`Epochs::split`）

1. $d_k=b_k(1-r_k)$；若 $\sum_k d_k>B_{\mathrm{rep}}$，所有 $d_k$ 按 $B_{\mathrm{rep}}/\sum d$ 等比例缩小。
2. $T_k=(b_k-d_k)z_k$；实体的整数权重为 $\lfloor T_k\cdot10^6/\sum_j T_j\rfloor$。合计可能比 $10^6$ 少，差额小于实体数，不再分配。
3. 实体的整数权重按成员原始权重向下取整分给各成员，余数归该实体按公钥排序的第一个成员。
4. 法定集合：份额之和超过总和的 2/3。

## 3. 纪元与交接（`consensus/src/epoch.rs`、`core.rs`）

- **终止块：**$G_e$ 是账本上纪元 $e$ 中第一个视图号不小于 $v(G_{e-1})+25$ 的块，$G_0$ 为创世块。视图号按编号计，跳过的视图也算。
- **H1：**$W_{e+2}$ 在账本到达 $G_e$ 时计算，节点持有 $G_{e+1}$ 的提交证明后生效。
- **H2：**纪元 $e+1$ 的块必须以节点自己的 $G_e$ 为祖先，否则不存储、不投票。
- **H3：**节点持有终止块的提交证明才进入新纪元，进入后不再签旧纪元的消息。
- **H4：**终止块之后的旧纪元块（后缀块）只用来认证终止块，内容不入账；诚实领导者把它们提议为空块。
- **领导者：**在有资格的成员中按纪元表权重抽取，随机数取 SHA-512$(e,v)$ 的前 8 字节，成员按公钥排序；新纪元的第一个视图仍由旧表的领导者主持。
- **块声明的表：**块摘要覆盖其纪元权重表的摘要（纪元号与按公钥排序的成员权重）；诚实节点只为声明了自己那张表的块投票；E2 只按块声明的表裁决。

## 4. 协议规则（`messages.rs`、`core.rs`）

| 编号 | 规则 |
|---|---|
| R1 | 签名带纪元号；投票签块哈希；块哈希覆盖内嵌 QC 所认证的块摘要与视图以及整张内嵌 TC |
| R2 | QC 逐签名者列出签名；TC 逐签名者保留其报告的 highQC 视图 $h_i$ 与 NR，并附最高 QC |
| R3 | 签名视图单调：签过视图 $v$ 的投票或超时后，不再为不高于 $v$ 的视图投票；超时每视图只签一次 |
| R5 | 超时所附 QC 的视图低于超时视图 |
| R6 | 超时报告的 $h$ 等于本地 highQC 视图；highQC 只增不减；收到 TC 时采纳其最高 QC |
| R8 | 上述签名状态持久化，进程重启不丢失（不做 fsync） |
| N6 | NR = 1 表示到超时为止没有同时收到领导者提案的块头和块数据；投过票的节点必须签 NR = 0 |
| 合法块 | 父块视图为 $v-1$，或块内嵌 TC$(v-1)$ 且父块视图不低于 $\max_i h_i$ |

## 5. G2（`aggregator.rs`、`inclusion.rs`、`reputation.rs`）

- **AT 指控：**某视图报告 NR = 1 的超时签名合计份额超过 2/3。
- **受保护交易：**由所有者签名并带序号；节点首次收到即转发给所有节点。
  - 证言：节点进入视图时，列出持有至少 $\Delta_g$（默认 500 ms）的待处理交易中按本地到达先后最早的至多 64 笔。
  - 打包：领导者按本地到达先后打包至多 1024 笔，冲突交易只取一笔。
  - 漏包事实：份额超过 2/3 的证言都列出、块被认证而仍不在链上的交易，按（视图，交易）各记一条。唯一的豁免是交易已作废。
  - 待处理状态不持久化。
- **CUSUM：**
  - 每个实体一条，以百万分之一计：有异常事实的视图加 1,609,438（ln 5），否则加 −587,787（ln 5/9），下限 0，达到 4,605,170（ln 10²）即判定。
  - 每个视图只计第一条事实。
  - 在 $G_e$ 处按视图顺序处理到 $v(G_e)+1-10$ 的视图（滞后 10 个视图）。已处理视图之后才上链的事实丢弃，不回放。
  - 观测按视图领导者计，领导者按指控所在纪元的表确定。
- **判定与排除：**
  - 判定后统计量清零，排除领导资格 500 个视图，排除期间不累积。
  - 同时被排除的基础权重不超过 50%，超出的按先进先出排队；排队超过 500 个视图即作废并清零。
- **信誉：**
  - 每次判定降 0.1，最低 0.7；排除期间不变。
  - 其余时间每 100 个视图恢复 0.02（25 视图纪元每纪元 0.005），最高 1。
  - 预算 $B_{\mathrm{rep}}=0.10$ 只作用于成表（§2），不改变信誉本身。

## 6. G1（`evidence.rs`、`punish.rs`）

- **证据：**E1 双签；E2 为非法块投票（按块声明的表判断）；E3 highQC 倒退；E-NR 投票后又签 NR = 1。
- **去重与有效期：**
  - 按（实体，证据类别，签名窗口）去重，签名窗口 100 个视图。
  - 签名早于其上链位置 6,400 个视图以上的证据不计；再犯回看期为 6,400 个视图。
- **关联份额 $c$：**签名窗口与 3,200 个视图链上窗口内同类证据份额的较大者。
- **定级（起始 + 再犯次数，按类封顶）：**

| 情形 | 起始 | 封顶 |
|---|---|---|
| 活性类（E-NR） | L1 | L3 |
| 安全类，$c\le$ cap | L2 | L4 |
| 安全类，cap < $c\le1/3$ | L3 | L4 |
| $c>1/3$ 或已分叉 | L4 | L4 |

- **处罚：**
  - L1 取消出块资格 100 个视图；L2 暂停 400 个视图；L3 暂停 3,200 个视图。
  - L4 在 200 个视图后由治理确认。分叉或恶意证据导致逐出；否则降级，再犯降为 L3，首犯降为 L2。
- **暂停上限：**同时被暂停的基础权重不超过 $L_{\max}=10\%$，超出的排队，排队期间取消出块资格。

## 7. 成表时的处理顺序

账本到达 $G_e$ 时，依次执行：
1. 收集 $G_e$ 及之前的事实，后缀块不计；
2. G2 按视图处理（§5）；
3. 更新信誉；
4. G1 定级、释放、排队暂停（§6）；
5. 成表（§2），得到 $W_{e+2}$。

## 8. 默认参数

| 参数 | 值 |
|---|---|
| cap（单实体上限） | 5%（小委员会须不小于 $(1-U)/n_L$，否则名册被拒绝） |
| $u_{\max}$（未认证类上限） | 25% |
| $L_{\max}$ | 10%，且不小于 cap |
| $B_{\mathrm{rep}}$ | 10% |
| 纪元长度 | 25 个视图 |
| 视图超时 | 1 秒（原型实验） |

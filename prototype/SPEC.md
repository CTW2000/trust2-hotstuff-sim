# 信任 2.0 现行规范（对应论文 v12 及之后，git 标签 `paper-v12`，2026-11-12）

这份文件只记录现行规则和默认参数，供独立实现逐位核对。规则的来龙去脉、历史配置和实验记录见 `DESIGN.md`，那里保留了已被替换的版本，不应当作规范引用。

- **G2：**时长按视图计。
- **G1 与信誉恢复：**按纪元计。它们以 100 个视图的参考纪元给出，再按纪元长度折算成纪元数（`epoch::scaled`，见 §6）。
- **纪元长度：**默认 25 个视图。一个纪元至少 25 个视图，因此按视图写出的 G1 时长是下限。

`scripts/replay_ref.py` 是按本文件写的整数参考实现，§9 的账本重放向量由它生成。

## 1. 名册与 CapNorm（`consensus/src/ttru.rs`）

- **实体：**
  - 同一受益所有人的节点合并为一个实体，原始权重 $w_k$ 为成员权重之和。
  - 实体按其第一个成员在公钥顺序中的位置编号。
  - 实体有一个未认证成员即属未认证类，否则属持牌类。
- **只计正权重：**原始权重为 0 的实体份额为 0，不计票、不参与领导者抽取，也不计入可行性判断。
- **未认证类份额：**$U=\min(\lfloor\sum_{k\in U}w_k\cdot10^{18}/\sum_k w_k\rfloor,\ u_{\max},\ n_U\cdot\mathrm{cap})$，其中 $n_U$ 为正权重的未认证实体数；持牌类分得 $10^{18}-U$。
- **拒绝名册（不放宽上限）：**以下情形 `base_weights` 返回 `Infeasible`：
  - 没有任何正权重（`Empty`）；
  - 没有正权重的持牌实体（`NoLicensed`）；
  - 某类的正权重实体数乘以 cap 小于该类份额（`Cap`）。
- **拒绝的后果：**
  - 创世名册被拒绝时，节点拒绝启动（`check_roster`，`node.rs`）。
  - 会使名册被拒绝的准入、退出、类别变更或合并不生效。这是方案规定；原型为固定名册。
  - 分叉逐出后余下名册被拒绝时，不重算，只把被逐出者的基础份额记为 0（`Punishment::evict`）。
- **注水封顶（`cap_normalize`）：**在一个类内把份额 $S$ 分给各实体。
  1. 每轮先令 $\mathit{rest}=S-\mathrm{cap}\cdot(\text{已固定数})$。
  2. 已固定的实体取 cap；未固定的实体取 $\lfloor w_k\cdot\mathit{rest}/\sum_{\text{未固定}}w\rfloor$，未固定实体的权重和为 0 时取 0。
  3. 凡结果超过 cap 的未固定实体改为固定，重新计算；直到某一轮没有新的固定。
- **定点：**份额以 $10^{18}$ 为 1，所有除法向下取整。

## 2. 纪元表（`ttru::table`、`Epochs::split`、`Epochs::make_table`）

1. $d_k=\lfloor b_k(10^6-r_k)/10^6\rfloor$，$r_k$ 以百万分之一计。若 $\sum_k d_k>B_{\mathrm{rep}}$，每个 $d_k$ 改为 $\lfloor d_k B_{\mathrm{rep}}/\sum_j d_j\rfloor$。
2. $T_k=(b_k-d_k)z_k$。实体的整数权重为 $\lfloor T_k\cdot10^6/\sum_j T_j\rfloor$，合计可能比 $10^6$ 少，差额小于实体数，不再分配。
3. 实体的整数权重按成员原始权重向下取整分给各成员，余数归该实体按公钥排序的第一个成员。
4. 成员可以当领导者，当且仅当其实体既未被 G2 排除，也未被 G1 取消出块资格。G1 取消出块资格包括 L1、暂停中、排队等待暂停和已逐出。
5. 法定集合：份额之和超过总和的 2/3。
6. 起始纪元及其下一个纪元的表都由名册直接算出（$r=1$，无处罚）。

## 3. 纪元与交接（`consensus/src/epoch.rs`、`core.rs`、`leader.rs`）

- **终止块：**$G_e$ 是账本上纪元 $e$ 中第一个视图号不小于 $v(G_{e-1})+25$ 的块，$G_0$ 为创世块，视图号为 0。视图号按编号计，跳过的视图也算。
- **H1：**$W_{e+2}$ 在账本到达 $G_e$ 时计算，节点持有 $G_{e+1}$ 的提交证明后生效。
- **H2：**纪元 $e+1$ 的块必须以节点自己的 $G_e$ 为祖先，否则不存储、不投票。
- **H3：**节点持有终止块的提交证明才进入新纪元，进入后不再签旧纪元的消息。
- **H4：**终止块之后的旧纪元块（后缀块）只用来认证终止块，内容不入账；诚实领导者把它们提议为空块。
- **纪元的视图范围：**视图 $v(G_e)+1$ 仍属纪元 $e$（$G_e$ 的子块）；纪元 $e+1$ 从视图 $v(G_e)+2$ 开始。
- **领导者抽取（`leader`）：**
  - **交接视图：**纪元 $e+1$ 的第一个视图 $v(G_e)+2$ 仍由旧表主持，领导者是该视图按 $W_e$ 抽出的成员。
  - **候选与权重：**其余视图只在权重为正、可以当领导者的成员中抽取，权重即表中的整数权重。若没有这样的成员，则全体成员各取权重 1。
  - **随机数：**$x$ 是 SHA-512 摘要的前 8 字节，按小端序读作 64 位无符号整数。摘要的输入是 16 字节小端序的纪元号，后接 8 字节小端序的视图号。
  - **选出：**取落点 $\lfloor x\cdot W/2^{64}\rfloor$（$W$ 为候选权重之和），候选按公钥升序累加权重，落点所在的成员即为领导者。
- **块声明的表：**块摘要覆盖其纪元权重表的摘要，即纪元号与按公钥排序的成员权重。诚实节点只为声明了自己那张表的块投票；E2 只按块声明的表裁决。

## 4. 协议规则（`messages.rs`、`core.rs`）

| 编号 | 规则 |
|---|---|
| R1 | 签名带纪元号；投票签块哈希；块哈希覆盖内嵌 QC 所认证的块摘要与视图以及整张内嵌 TC |
| R2 | QC 逐签名者列出签名；TC 逐签名者保留其报告的 highQC 视图 $h_i$ 与 NR，并附最高 QC |
| R3 | 签名视图单调：签过视图 $v$ 的投票或超时后，不再为不高于 $v$ 的视图投票；超时每视图只签一次 |
| R5 | 超时所附 QC 的视图低于超时视图 |
| R6 | 超时报告的 $h$ 等于本地 highQC 视图；highQC 只增不减；收到 TC 时采纳其最高 QC |
| R8 | 上述签名状态持久化，进程重启不丢失（不做 fsync） |
| N6 | NR = 1 表示到超时为止没有同时收到领导者提案的块头和块数据；投过票的节点必须签 NR = 0 |
| 合法块 | 父块视图为 $v-1$，或块内嵌 TC$(v-1)$ 且父块视图不低于 $\max_i h_i$ |

## 5. G2（`aggregator.rs`、`inclusion.rs`、`reputation.rs`）

- **AT 指控：**某视图报告 NR = 1 的超时签名合计份额超过 2/3。指控带视图号和所在纪元号。
- **受保护交易：**由所有者签名并带序号；节点首次收到即转发给所有节点。
  - 证言：节点进入视图时，列出持有至少 $\Delta_g$（默认 500 ms）的待处理交易中，按本地到达先后最早的至多 64 笔。
  - 打包：领导者按本地到达先后打包至多 1024 笔，冲突交易只取一笔。
  - 漏包事实：份额超过 2/3 的证言都列出、块被认证而仍不在链上的交易，按（视图，交易）各记一条。唯一的豁免是交易已作废。
  - 待处理状态不持久化。
- **记录事实：**
  - 账本上的指控和成立的漏包证明，都是其视图的异常事实。
  - 每个视图只保留第一条事实及其纪元号。
  - 视图号不大于已处理视图的事实丢弃，不回放。
- **CUSUM：**每个实体一条，以百万分之一计。异常增量 +1,609,438（ln 5），正常增量 −587,787（ln 5/9），下限 0，判定阈值 4,605,170（ln 10²）。
- **按视图处理：**在 $G_e$ 处，按顺序处理上次之后到 $v(G_e)+1-10$ 为止的每个视图 $u$（滞后 10 个视图）。每个视图依次做三步：
  1. **释放：**排除期满（截止视图不大于 $u$）的实体释放。
  2. **队列：**从队首起逐个处理。
     - 等待超过 500 个视图的作废，统计量清零。
     - 其余的，若尚无受阻者、本身未被排除且还有余量，则予以排除。
     - 否则留在队中；它若未被排除，其后的都受阻（严格先进先出）。
  3. **观测：**取 $u$ 的领导者所在实体。
     - 领导者的确定：有事实时按事实所带纪元的表，否则按 $u$ 所在纪元的表。
     - 该实体正被排除时跳过；否则按 $u$ 有无事实加相应增量。
     - 达到阈值即判定：
       - 已在队中的，统计量保持在阈值；
       - 队列为空且有余量的，排除；
       - 否则入队，统计量清零。
- **排除：**
  - 排除 500 个视图（截止视图 = 排除时的视图 + 500），统计量清零，排除期间不累积。
  - 余量指：同时被排除的实体的基础份额（创世名册的 CapNorm 结果）加上本实体，不超过 50%。
- **信誉：**处理完各视图后更新：
  - 本次被排除（含从队列中排除）的实体降 0.1，最低 0.7；入队本身不降。
  - 仍在排除期的实体不变。
  - 其余实体每个纪元恢复 $20{,}000\cdot\text{纪元长度}/100$ ppm（25 视图纪元为 5,000），最高 $10^6$。
  - 预算 $B_{\mathrm{rep}}=0.10$ 只作用于成表（§2），不改变信誉本身。

## 6. G1（`evidence.rs`、`punish.rs`）

- **证据：**
  - 安全类：E1 双签；E2 为非法块投票（按块声明的表判断）；E3 highQC 倒退。
  - 活性类：E-NR，投票后又签 NR = 1。
  - 每份证据带被指控者、签名纪元 $e_s$ 和上链纪元 $e_c$（所在块的纪元）。
- **时长折算：**参考纪元数 $n$ 折算为 $\max(1,\lfloor(100n+\ell/2)/\ell\rfloor)$ 个纪元，$\ell$ 为纪元长度。默认值如下：

| 时长 | 参考纪元数 | 25 视图纪元下的纪元数 |
|---|---|---|
| L1 取消出块资格 | 1 | 4 |
| 签名窗口 | 1 | 4 |
| L2 暂停 | 4 | 16 |
| L3 暂停 | 32 | 128 |
| 链上窗口 | 32 | 128 |
| 有效期与再犯回看期 | 64 | 256 |
| L4 治理延迟 | 2 | 8 |

- **生效时间：**纪元 $e$ 中上链（$G_e$ 及之前）的证据在 $W_{e+2}$ 生效。成 $W_k$ 时，收入所有 $e_c<k$ 的待处理证据，按上链顺序加入。
- **有效期：**$e_c-e_s$ 大于回看期的证据在上链时即丢弃。
- **去重：**签名窗口按签名纪元号对齐，即 $\lfloor e_s/\text{签名窗口}\rfloor$ 相同的证据属同一窗口。同一（实体，类别，签名窗口）只记一项，后来的证据只用于升级。
- **再犯次数：**一项证据第一次定级时计算，等于同一实体、同一类别、已定级且上链纪元不早于 $e_c-$回看期的项数。
- **关联份额 $c$（安全类）：**取以下两者的较大者，均按创世名册的基础份额计、每个实体只计一次。
  - 签名窗口相同的安全类证据涉及的实体份额之和；
  - 若 $e_c+$链上窗口 $>k$：上链纪元在 $(k-\text{链上窗口},\,k]$ 内的安全类证据涉及的实体份额之和。
- **定级：**每次成表时按证据项的加入顺序逐项重新计算，等级只升不降，升级即执行新等级。等级 = 起始等级 + 再犯次数，按类封顶：

| 情形 | 起始 | 封顶 |
|---|---|---|
| 活性类（E-NR） | L1 | L3 |
| 安全类，$c\le$ cap | L2 | L4 |
| 安全类，cap < $c\le1/3$ | L3 | L4 |
| $c>1/3$ 或已分叉 | L4 | L4 |

- **处罚：**
  - L1 取消出块资格到 $k+$L1 时长（不含）。
  - L2、L3 请求暂停相应时长：
    - 已在暂停中的，从原起点按新时长延长（只延不缩）；
    - 已在队中的，取较长的时长；
    - 否则入队。
  - L4 在治理延迟后由治理确认：分叉或恶意证据导致逐出；否则降级，再犯降为 L3，首犯降为 L2。
- **成表顺序：**
  1. 收入证据并定级；
  2. 执行到期的治理决定；
  3. 释放截止纪元不大于 $k$ 的暂停；
  4. 按先进先出处理暂停队列：暂停后的基础份额合计不超过 $L_{\max}$ 的予以暂停（截止纪元 = $k$ + 时长），第一个放不下的及其后的都留在队中。
- **暂停上限：**$L_{\max}$ 取配置值与最大基础份额中的较大者。排队期间取消出块资格。

## 7. 成表时的处理顺序

账本到达 $G_e$ 时，依次执行：
1. 收集 $G_e$ 及之前的事实，后缀块不计；
2. G2 按视图处理（§5）；
3. 更新信誉；
4. G1 定级、释放、排队暂停，目标为 $W_{e+2}$（§6）；
5. 成表（§2），得到 $W_{e+2}$；
6. 进入纪元 $e+1$，记下其交接视图与交接领导者（§3）。

## 8. 默认参数

| 参数 | 值 |
|---|---|
| cap（单实体上限） | 5%（小委员会须不小于 $(1-U)/n_L$，否则名册被拒绝） |
| $u_{\max}$（未认证类上限） | 25% |
| $L_{\max}$ | 10%，且不小于 cap |
| $B_{\mathrm{rep}}$ | 10% |
| 纪元长度 | 25 个视图 |
| 视图超时 | 1 秒（原型实验） |

### 账本重放向量

向量给出两段已提交账本：
- `small-committee`：7 个成员，886 个块，39 个终止块；
- `default-caps`：23 个成员，默认上限，326 个块，13 个终止块。

每个块只有视图号、纪元号、指控（视图，纪元）和证据（成员，E1 或 E-NR，签名纪元）。

期望结果：
- 实体编号与基础份额；
- 每个终止块的视图号；
- 每个终止块处：已处理到的视图、G2 与 G1 事件、各实体的 CUSUM、信誉、排除、$z$、出块资格和两个队列；
- 每个纪元的权重表（整数权重、能否当领导者、交接视图及其领导者）；
- 每个视图的领导者。

覆盖的情形：
- **事实与时序：**迟到事实（恰为已处理视图的丢弃、下一视图的计入）；滞后期内留到下一个终止块的事实；无异常视图的负增量；后缀块里的指控和证据被忽略；无块无指控的超时视图使终止块后移。
- **G2：**排除、50% 上限下的排队与出队、释放、恢复、预算触顶。
- **G1：**同一签名窗口去重、L1 到再犯 L2、关联份额超过 cap 的 L3、$L_{\max}$ 排队、暂停期满释放。
- **领导者与表：**交接视图由旧表领导者主持；零权重成员；多成员实体的余数归属；$n_U\cdot\mathrm{cap}$ 约束未认证类份额。

未覆盖：漏包证明（在账本上与指控同为该视图的异常事实）、分叉逐出与治理确认的恶意、G2 排队作废、信誉下限 0.7、证据有效期。

**原型核对：**`epoch::replay_tests` 用 `Epochs` 按 `Core::commit` 的方式重放，以上各项逐位一致。

**区分能力：**`scripts/replay_mutants.py` 把参考实现改成 14 种常见的错误实现，每一种都会使向量对不上。例如：
- 后缀块内容计入；
- 滞后取 0 或 5；
- 纪元号按 8 字节编码；
- 恢复未按纪元长度折算；
- G1 时长未折算；
- 余数归最后一个成员；
- 不取 $n_U\cdot\mathrm{cap}$；
- 交接视图不保留旧领导者；
- 下一张表只提前一个纪元确定。

### 运行

从仓库根目录执行：
- `python3 prototype/scripts/gen_replay_vectors.py`：生成重放向量，只用标准库；
- `python3 prototype/scripts/replay_mutants.py`：检查区分能力；
- 其余三套向量的生成脚本也在 `prototype/scripts/`，以 `PYTHONPATH=.` 运行。
